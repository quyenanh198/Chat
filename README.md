# Lazybutts

Lazybutts is a self-hosted, ephemeral chat PWA (Snapchat-style disappearing messages, media, and stories) built for a small family/friends group running on a home server.

## Features

- **Invite-only accounts.** The first user to register becomes admin automatically; everyone after that needs a single-use invite code generated by an admin.
- **Self-destructing text.** Every text message expires 24h after it's sent.
- **Self-destructing media.** Photos/videos follow the sender's `media_mode` setting at send time:
  - `once` (default) — each recipient can open it exactly once (a second attempt gets `403`); the file and message are deleted once every recipient has viewed it, or after 24h, whichever comes first.
  - `24h` — viewable as many times as you like for 24h, then it's gone.
  - The sender can re-view their own media as many times as they like — but only until the message itself is gone: destroyed early once every recipient has viewed it (`once` mode), or expired after 24h either way. The sender's own views are never counted towards that "every recipient has viewed it" destruction trigger.
- **24h stories**, visible to everyone in the app, viewable repeatedly, with per-user view tracking.
- **1-1 and group chat** over a small REST API, with live updates pushed over WebSocket and Web Push notifications for anyone without an open connection.
- **PWA**: installable to the home screen, with a service worker for push notifications and app-shell caching.
- A background cleanup job sweeps expired rows and their files every 60 seconds.

Out of scope for this MVP: end-to-end encryption, calls, filters, reactions, typing indicators, password change, account deletion, renaming a group after creation.

## Stack

- **Server**: Node 22, Fastify 5, `@fastify/websocket`, `@fastify/cookie`, `@fastify/multipart`, `@fastify/static`, better-sqlite3, web-push, argon2, JWT (`jose`). Tests: Vitest + `fastify.inject`.
- **Web**: React 18 + Vite + TypeScript, React Router, plain CSS (dark, mobile-first).
- **Packaging**: one Docker image — a multi-stage build that compiles the web app and serves it (plus the API) from a single Fastify process.

## Environment variables

| Variable | Required | Default | Notes |
| --- | --- | --- | --- |
| `SESSION_SECRET` | **yes** | — | Signs the session JWT (cookie `lb_session`). The server refuses to start without it. Use a long random string. |
| `PORT` | no | `8082` | HTTP port the server listens on. |
| `DATA_DIR` | no | `/data` | SQLite DB lives at `$DATA_DIR/db/lazybutts.sqlite3`, uploaded media at `$DATA_DIR/media`. Both are created on startup if missing. |
| `MAX_UPLOAD_MB` | no | `50` | Per-upload size cap for media/story uploads. |
| `VAPID_PUBLIC_KEY` | no | — | Web Push VAPID public key. Push is silently disabled (no-op) unless all three `VAPID_*` vars are set. |
| `VAPID_PRIVATE_KEY` | no | — | Web Push VAPID private key. |
| `VAPID_SUBJECT` | no | — | Contact URI for push, e.g. `mailto:you@example.com`. |
| `BOOTSTRAP_INVITE` | no | — | When set, the very first registration (the one that becomes admin with no invite otherwise) must also supply `invite` equal to this value. Closes the window where anyone who reaches the app before the real admin registers gets to claim the admin account. Leave unset to keep the default "first register wins" behavior — see the deploy note below. |

Generate a VAPID key pair with:

```bash
npx web-push generate-vapid-keys
```

## Dev quickstart

**Server** (from `server/`):

```bash
npm i
npm test               # 130 tests, vitest
SESSION_SECRET=devsecret DATA_DIR=/tmp/lazybutts-dev node src/server.js
```

The server listens on `:8082` and serves `GET /api/*` plus `GET /ws` (WebSocket). It also serves `web/dist` at `/` with an SPA fallback whenever that directory has been built (see below) — harmless to leave unbuilt while iterating on the API.

**Web** (from `web/`, in a second terminal):

```bash
npm i
npm run dev             # Vite dev server on :5173, proxies /api and /ws to :8082
npm run build           # production build -> web/dist
npx tsc --noEmit        # typecheck
```

## Smoke test

`scripts/smoke.sh` boots a real server against a throwaway SQLite DB and walks the core happy path end to end over HTTP: register admin → `GET /me` → admin creates an invite → register a second user with it → 1-1 conversation → send a text message → read it back. If `web/dist` has been built it also checks that `GET /` serves the SPA shell.

```bash
cd web && npm run build   # optional — build first so the static-serving check runs too
cd ..
bash scripts/smoke.sh
```

Exits `0` only if every step passes; the server process and temp data directory are cleaned up automatically on exit (success or failure).

## Production (Docker)

> **Before you expose this to the internet:** registration is invite-only, but the very *first* account gets in with no invite at all and becomes admin — whoever registers first, wins. Either register the admin account yourself before pointing DNS/a reverse proxy at the container, or set `BOOTSTRAP_INVITE` so the first registration also has to know a shared secret (see the env table above).

The root `Dockerfile` is a two-stage build: it compiles the web app with Node, then copies the built assets into a second, `--omit=dev` runtime image alongside the server source. It exposes one process on port `8082` — no reverse proxy needed in front of it for routing; Fastify serves both the API and the SPA. The runtime image runs as the non-root `node` user (not root).

```bash
docker build -t lazybutts .

docker run -d \
  --name lazybutts \
  -p 8082:8082 \
  -e SESSION_SECRET="$(openssl rand -hex 32)" \
  -e VAPID_PUBLIC_KEY=... \
  -e VAPID_PRIVATE_KEY=... \
  -e VAPID_SUBJECT="mailto:you@example.com" \
  -v lazybutts-db:/data/db \
  -v lazybutts-media:/data/media \
  lazybutts
```

Mount `/data/db` and `/data/media` as persistent volumes (or bind mounts to an external drive) — that's the entire durable state of the app.

Since the container runs as the non-root `node` user, that path has to be writable by it: a named Docker volume (as in the example above) is created empty and already owned by `node`, so it just works. A **bind mount to a host directory** instead keeps that directory's own ownership — either `chown` it on the host to match the `node` user/group inside the image, or run the container with `--user "$(id -u):$(id -g)"` (or another UID that already owns the directory) to override it.

## Hub integration (macmini-hub)

Lazybutts is meant to run as a service inside the `macmini-hub` docker-compose stack, added as a git submodule at `apps/chat`:

```bash
git submodule add <this-repo-url> apps/chat
```

The hub's compose file expects the prebuilt image `ghcr.io/quyenanh198/chat:latest` (built by this repo's CI from the `Dockerfile` above) and mounts `/data/db` and `/data/media` from the hub's external volume, same as any other hub service. Add to the hub's compose env for this service:

```yaml
environment:
  SESSION_SECRET: ${LAZYBUTTS_SESSION_SECRET}
  VAPID_PUBLIC_KEY: ${LAZYBUTTS_VAPID_PUBLIC_KEY}
  VAPID_PRIVATE_KEY: ${LAZYBUTTS_VAPID_PRIVATE_KEY}
  VAPID_SUBJECT: ${LAZYBUTTS_VAPID_SUBJECT}
```

The chat subdomain is expected to bypass Cloudflare Access at the hub's edge — this app manages its own auth (invite-only registration + session cookie), so it doesn't need to sit behind the hub's SSO.
